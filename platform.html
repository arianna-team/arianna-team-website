SBOM & HBOM

A complete model of your device

Everything starts with the Device Model: one per device design, with its hardware (HBOM) and software (SBOM) in one place.

Organised like your architecture. Every MCU, MPU, secure element and module, each with its own components and interfaces.
One version per firmware release. Existing triage decisions and assessments carry over, while vulnerabilities affecting components that have been removed or updated are automatically closed when no longer applicable.
SCA tools

Accurate SBOMs, straight from your build

ARIANNA's own Software Composition Analysis tools are lightweight scripts (Python, Bash or PowerShell) with no external dependencies. Run them on their own or inside your CI/CD pipeline.

The most accurate SBOM, without sharing your code. No guessing from binaries, so no missing components or wrong versions. You keep full control of your proprietary software.
CI/CD pipeline integration. Run the tools after each release; results upload through the REST API and start a new assessment.

Continuous monitoring

Every component, checked every day

Every component is checked daily against ARIANNA's vulnerability database, built from public sources and curated by our security team.

Daily vulnerability mapping. Every component is mapped to new vulnerabilities each day, so you stay in control of your security posture and, thanks to our prioritisation filters, know what to address first.
Vulnerability enrichment. Exploitation data from CISA KEV and ENISA EUVD, canary and honeypot systems, and ARIANNA's own verified intelligence.

Automatic assessment & prioritisation

Focus on the most important vulnerabilities first

Before your team looks at anything, ARIANNA removes what doesn't apply and ranks the rest. Final decisions always stay with your security experts.

Automatic applicability analysis. When the vulnerable version is removed, updated or patched in the build, findings are adjusted or discarded automatically.
Pre-triage & prioritisation engine. Every open vulnerability is marked High or Low priority by your own rules, either risk-based or exploitability-based.
Remediation & policies

A clear path from triage to closure

A four-stage pipeline covers the whole life of a vulnerability. Every status change, note and risk update is recorded, so each decision is traceable in an audit.

Four stages, one pipeline. From identification and triage to addressing, and finally closing or disclosing each vulnerability.
Deadlines by risk level. Set from your policies or contracts, with reminders before they expire.
Automatic closure. A firmware update that fixes the component closes the vulnerability.

Integrations & API

Fits the way your teams already work

Product security works in ARIANNA; developers keep their own tools. Both stay in sync.

Issue trackers (Jira, Redmine, GitHub Issues). Send a vulnerability to development with the affected component, severity, recommended fix and advisories. Status syncs back, and the security team is told when the issue closes.
CI/CD & REST API. Run the SCA tools in your pipeline after each release, upload the result through the REST API, and start a new assessment automatically.
